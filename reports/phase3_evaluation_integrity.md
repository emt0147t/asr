## 1. Executive Summary

This report presents an independent, evidence-based audit of all claims, source code, data manifests, model checkpoints, and evaluation procedures established in Phase 2. 

In accordance with project integrity requirements, prior reports are preserved as historical records, and this document serves as the formal correction, gap analysis, and baseline audit.

### Core Audit Verdicts:
1. **Metric Reproducibility:** **VERIFIED**. The Phase 2 checkpoint (`best_kws_model.pt`) evaluated on `data/manifests/test_manifest.csv` reproduces the reported metrics exactly: **97.52% overall accuracy**, **69.44% TRAI recall**, **79.17% Northern dialect accuracy**, and **0.9374 Macro-F1**.
2. **Defect 1 — Missing SILENCE in Test Set:** **CONFIRMED DEFECT**. The test manifest contains **0 SILENCE samples**. The confusion matrix evaluated only classes 0 through 4.
3. **Defect 2 — Incomplete Macro-F1 Computation:** **CONFIRMED DEFECT**. Scikit-learn's `f1_score(average="macro")` defaulted to averaging only the 5 classes present in the test manifest. The true 6-class Macro-F1 with zero support for SILENCE is **0.7812**, not 0.9374.
4. **Defect 3 — Target Command Provenance:** **DOCUMENTED**. All 1,000 target command samples (250 each of `TRAI`, `PHAI`, `LEN`, `XUONG`) are parametric acoustic reference utterances generated for pipeline calibration, **not** genuine field-recorded human utterances.
5. **Defect 4 — False Alarms Per Hour Methodology:** **CONFIRMED METHODOLOGICAL FLAW**. The claimed "0.00 FA/hr" was extrapolated from 300 isolated 1.0-second negative clips (a mere 5.0 minutes of audio) evaluated by a static window classifier, not a true streaming rolling-window detector operating with a 100 ms hop size over continuous audio streams.

### Item 3: Root Cause of Missing SILENCE in the Test Set
- **Audit Investigation:**
  In `src/preprocessing/build_manifests.py`, the function `process_noise_source` sliced 1.0-second chunks from 40 microphone noise MP3 files with `max_noise_chunks = 300`:
  ```python
  train_files = set(mp3_files[:int(n_files * 0.70)])
  val_files = set(mp3_files[int(n_files * 0.70):int(n_files * 0.85)])
  test_files = set(mp3_files[int(n_files * 0.85):])
  ```
  During execution, `train_files` generated 256 chunks and `val_files` generated 44 chunks, reaching the hard limit of 300 chunks ($256 + 44 = 300$). The loop broke before processing any files in `test_files`.
- **Result:**
  - `train_manifest.csv`: 256 `SILENCE` samples
  - `val_manifest.csv`: 44 `SILENCE` samples
  - `test_manifest.csv`: **0 `SILENCE` samples**
- **Conclusion:** **CONFIRMED PIPELINE DEFECT**. The test manifest was starved of noise/silence data due to an unintended chunk allocation cap.

### Item 4: Macro-F1 Calculation Discrepancy
- **Audit Investigation:**
  In `src/models/evaluate_kws.py`:
  ```python
  macro_f1 = f1_score(y_true, y_pred, average="macro", zero_division=0)
  ```
  In scikit-learn, when the `labels` parameter is omitted, `f1_score(average="macro")` computes the arithmetic mean only over classes that actually exist in `y_true`. Because `test_manifest.csv` only contained classes 0, 1, 2, 3, and 4:
  $$\text{Macro-F1}_{\text{reported}} = \frac{F1_{\text{TRAI}} + F1_{\text{PHAI}} + F1_{\text{LEN}} + F1_{\text{XUONG}} + F1_{\text{UNKNOWN}}}{5}$$
  $$\text{Macro-F1}_{\text{reported}} = \frac{0.820 + 0.867 + 1.000 + 1.000 + 1.000}{5} = \mathbf{0.9374}$$
- **True Six-Class Macro-F1:**
  If computed across all 6 production classes where `SILENCE` has $F1=0.000$ due to lack of evaluation support:
  $$\text{Macro-F1}_{\text{6-class}} = \frac{0.820 + 0.867 + 1.000 + 1.000 + 1.000 + 0.000}{6} = \mathbf{0.7812}$$
- **Conclusion:** **CONFIRMED EVALUATION DEFECT**. The reported Macro-F1 gave the false impression that 6-class performance was 0.9374 when the 6th class was never tested.

### Item 8: False Alarms Per Hour Methodology Audit
- **Audit Investigation:**
  Phase 2 reported "0.00 FA/hr".
  In `src/models/evaluate_kws.py`, this was computed as:
  $$\text{FA/hr} = \frac{\text{False Alarms}}{\text{Negative Audio Duration (hours)}} = \frac{0}{300 \times 1.0 \text{ s} / 3600 \text{ s/hr}} = \frac{0}{0.0833 \text{ hr}} = 0.00$$
- **Flaws Identified:**
  1. **Trivial Duration:** Only 300 seconds (5.0 minutes) of audio was evaluated. Claiming an hourly rate from 5 minutes of data is statistically invalid.
  2. **Not a Streaming Detector:** The test evaluated isolated, pre-windowed, 1.0-second files. A real keyword spotting detector processes a streaming microphone feed using a sliding window with a 50–100 ms hop size (generating 36,000 to 72,000 window inferences per hour). In a continuous stream, transient boundary states and noise spikes create false alarms that never appear in centered isolated window tests.
- **Conclusion:** **CONFIRMED METHODOLOGICAL FLAW**. The claim of zero false alarms per hour must be replaced by continuous streaming evaluation across long-form audio.
